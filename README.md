# ФлораПлан — планирование закупок и продаж цветочной продукции

**Тема:** «Разработка информационной системы планирования процессов закупки и продажи цветочной продукции».

В репозитории — сама информационная система «ФлораПлан» и результаты практических работ по курсу «Программная инженерия» (ТулГУ, ИПМКН). Для системы выполнены обследование и анализ осуществимости, сформулированы требования и ТЗ по ГОСТ 34.602-89, построены функциональная (IDEF0, IDEF3) и объектная (UML) модели и план проекта, а затем система реализована по этому ТЗ: веб-приложение для всех ролей, REST API, обмен с «1С:Розница» и интернет-магазином.

> Ветка [`ml`](../../tree/ml) — задел для ВКР: та же система с прогнозированием спроса методами машинного обучения (прототип на градиентном бустинге). В `main` прогноз строится статистическими методами анализа временных рядов.

> **Редакции.** Здесь, в `main`, — полная редакция для сети магазинов: роли, PostgreSQL, Docker, обмен с «1С» и интернет-магазином (релизы `v*`). Для одного салона на одном ПК есть [базовая редакция](../../tree/coursework) на Flask и SQLite: без сервера и администрирования, работает без интернета (релизы `basic-v*`). Ветки не сливаются: у каждой редакции свой цикл выпуска.

## Идея системы

Срезанные цветы — скоропортящийся товар: срок реализации у них 5–14 дней. Спрос при этом резко скачет перед 14 февраля, 8 марта, 1 сентября и Новым годом. Ошибка в закупке приводит либо к **списаниям** (у компании они доходили до 15–18 % закупочной стоимости), либо к **дефициту** в пиковые дни.

Система делает четыре вещи:

- ведёт **партионный учёт** со сроками реализации (принцип FEFO — первым истекает, первым продаётся);
- строит **прогноз спроса** по товарам и торговым точкам на 14 дней с квантилями P50, P80, P95;
- формирует **рекомендуемый заказ поставщику** по модели «продавца газет» с учётом остатков, сроков поставки, кратности упаковки и бюджета;
- рекомендует **уценку** партий, у которых истекает срок, и ведёт аналитику списаний.

| Подсистема | Назначение |
|---|---|
| НСИ | Номенклатура, поставщики, условия поставки, торговые точки, календарь праздников |
| Учёт запасов и партий | Приёмка (ТСД), партии со сроками, остатки, перемещения |
| Учёт продаж и заказов | Кассы и «1С:Розница», интернет-магазин, предзаказы, резервирование |
| Прогнозирование спроса | Подготовка данных, расчёт прогноза и квантилей, контроль точности (WAPE, bias) |
| Планирование закупок | Расчёт заказов, сценарии праздников, согласование, отправка |
| Сроки и уценка | Контроль «годен до», рекомендации по скидкам, списание |
| Аналитика | ABC/XYZ, оборачиваемость, доля списаний, точность прогноза |

## Прогнозирование и расчёт заказа

- **Модели:** сезонная наивная, Хольт–Уинтерс (экспоненциальное сглаживание с сезонностью), метод Кростона для прерывистого спроса; для каждого ряда выбирается модель с наименьшей ошибкой на отложенном периоде.
- **Квантили** P50, P80, P95 — по распределению ошибок прогноза на истории.
- **Праздники** — календарные коэффициенты и сценарии, утверждённые менеджером.
- **Метрики:** WAPE и bias; новая версия модели публикуется, только если её WAPE не хуже действующей.
- **Заказ:** целевой уровень обслуживания α = Cu / (Cu + Co), где Cu — упущенная маржа, Co — потери от списания; Q = max(0, D(L+T) − S − Z), округление вверх до кратности упаковки.

## Запуск

**Windows без установки.** Скачайте `FloraPlan-<версия>-windows-x64.zip` со страницы [Releases](../../releases), распакуйте и запустите `ФлораПлан.exe`. При первом запуске программа предложит загрузить демо-данные.

**Сервер в Docker** (PostgreSQL, API, планировщик, nginx с интерфейсом):

```
cd deploy
cp .env.example .env      # задайте пароли
docker compose up -d --build
```

**Из исходников** (Python 3.12, Node.js 22):

```
cd frontend && npm ci && npm run build      # интерфейс собирается в backend/floraplan/static
cd ../backend && pip install -e ".[dev]"
floraplan demo        # демо-данные: справочники, два года продаж, прогнозы
floraplan run         # http://127.0.0.1:8000/, API — /api/docs
```

Вход: `admin`/`admin`; демо-пользователи `director`, `buyer`, `storekeeper`, `florist`, `shop`, `analyst` с паролем `demo`.

Документация: [руководство пользователя](docs/USER_GUIDE.md), [руководство администратора](docs/ADMIN_GUIDE.md), [интеграция с «1С» и интернет-магазином](docs/INTEGRATION.md), [описание релиза](docs/RELEASE_NOTES.md).

**Проверки:** `pytest` в `backend` (модульные и API-тесты на SQLite и PostgreSQL), `tests_e2e` — сквозные тесты интерфейса на Playwright, `loadtest` — нагрузочный тест на Locust (30 пользователей, пиковый день). Тесты запускаются в GitHub Actions при каждом push; релиз собирается по тегу `v*`.

## Структура репозитория

```
backend/     сервер: FastAPI, SQLAlchemy, миграции Alembic, прогнозирование, планировщик задач, тесты
frontend/    веб-интерфейс: React + TypeScript
deploy/      Docker Compose: PostgreSQL, backend-api, scheduler, web-frontend
packaging/   сборка Windows-версии (PyInstaller)
docs/        руководства пользователя и администратора, интеграция, описание релиза
reports/     отчёты по практическим работам (DOCX + PDF)
diagrams/    диаграммы: IDEF0, IDEF3, VORD, ER, UML, сетевой график, Гант
tools/       генератор отчётов (python-docx + MS Word) — исходники текста и диаграмм
```

Отчёты собираются генератором из `tools/report_generator` (`python build.py`). Ему нужны Windows, MS Word, Java и [`plantuml.jar`](https://github.com/plantuml/plantuml/releases), положенный рядом со скриптами. Данные титульного листа (и поле «АВТОР» в бланках IDEF) задаются в `config.py`.
