# ФлораПлан Базовая — учёт продаж и планирование закупок для одного цветочного салона

**Тема:** «Разработка информационной системы планирования процессов закупки и продажи цветочной продукции».

Это ветка `coursework`, **базовая редакция** «ФлораПлана», версия **1.2.0**. Небольшое веб-приложение на Python (Flask) и SQLite. Работает на одном компьютере салона, без сервера и без администратора. Полная редакция для сети магазинов находится в ветке [`main`](../../tree/main).

## Зачем отдельная базовая редакция

Так устроен рынок учётных программ: один продукт выпускается в нескольких редакциях под заказчиков разного размера. Например, у «1С:Розница» есть «Базовая» и «ПРОФ». Базовая рассчитана на один магазин и одного пользователя и не требует администрирования. ПРОФ нужна сети магазинов с несколькими сотрудниками и обменом данными.

С «ФлораПланом» то же самое. Типичный небольшой салон — это один кассир-флорист на одном ПК. Такому салону не нужны:

- **сервер PostgreSQL и Docker** — их надо устанавливать, обновлять, резервировать и защищать;
- **роли и права доступа** — с программой работает один человек;
- **обмен с «1С» и интернет-магазином** — у салона нет ни того, ни другого.

Для него всё это — лишние затраты на внедрение и сопровождение (совокупная стоимость владения, TCO). Нанимать ИТ-специалиста ради программы салон не будет.

Базовая редакция решает эту задачу:

- **не требует администрирования:** база данных SQLite — это один файл `floraplan.db` рядом с программой; резервная копия — копия этого файла;
- **работает на слабом ПК:** нужен только Python, памяти расходуется в разы меньше, чем у полной редакции;
- **работает без интернета:** всё нужное лежит в архиве релиза, включая пакеты для установки (папка `wheels`);
- **ставится за минуту:** распаковать архив и дважды щёлкнуть `run.bat`.

Ядро предметной логики в обеих редакциях одно: партионный учёт со сроками, продажа по FEFO, прогноз спроса, расчёт заказа с учётом упаковки. Салон, который вырос до нескольких магазинов, переходит на полную редакцию.

| | Базовая (эта ветка) | Полная ([`main`](../../tree/main)) |
|---|---|---|
| Для кого | Один салон, один ПК | Сеть магазинов, склад, интернет-магазин |
| База данных | SQLite (один файл) | PostgreSQL или SQLite |
| Пользователи | Один (`admin`) | Ролевой доступ: директор, закупщик, кладовщик, флорист, аналитик и др. |
| Прогноз спроса | Скользящее среднее за 14 дней | Хольт–Уинтерс, Кростон, сезонная наивная модель; квантили P50/P80/P95; праздники |
| Расчёт заказа | $`\bar{y} \cdot (L + 3) \cdot 1{,}2 - S`$ с округлением до упаковки | Модель «продавца газет», бюджет, согласование, отправка поставщику |
| Интеграции | Нет | «1С:Розница», интернет-магазин, e-mail и API поставщиков |
| Установка | `run.bat`, нужен только Python | Windows-сборка или Docker Compose |
| Сопровождение | Не требуется | Резервное копирование, планировщик, обновления |
| Объём кода | ≈ 800 строк | ≈ 10 000 строк |

## Что умеет

- **Товары и поставщики:** справочники с ценой, закупочной ценой, сроком реализации и кратностью упаковки.
- **Приём поставки:** приход партии; срок годности = дата приёмки + срок реализации товара.
- **Продажи по FEFO** (First Expired — First Out): товар списывается сначала из партии, у которой раньше кончается срок. Просроченные партии не продаются.
- **Остатки:** партии подсвечиваются — жёлтым, если срок истекает (≤ 2 дней), красным, если истёк; списание с причиной.
- **Прогноз спроса:** скользящее среднее — средние продажи в день за последние 14 дней.
- **Расчёт заказа поставщику:**

  ```math
  Q = \left\lceil \frac{\bar{y} \cdot (L + 3) \cdot 1{,}2 - S}{m} \right\rceil \cdot m,
  ```

  где $`\bar{y}`$ — средние продажи в день за 14 дней, $`L`$ — срок поставки в днях (+3 дня до следующего заказа), $`S`$ — остаток годных партий, $`m`$ — кратность упаковки; 1,2 — страховой запас 20 %. Если остатка хватает, заказ равен нулю.
- **Отчёт за 30 дней:** выручка по товарам и потери от списаний.

## Установка и запуск

Нужен Python 3.11 или новее ([python.org](https://www.python.org/downloads/), при установке отметить «Add python.exe to PATH»).

**Из релиза (без интернета).** Скачайте `FloraPlan-Basic-<версия>.zip` со страницы [Releases](../../releases), распакуйте и дважды щёлкните `run.bat`. При первом запуске программа создаст окружение, загрузит демо-данные и откроет браузер. Чтобы остановить программу, закройте окно консоли.

**Из исходников:**

```
cd app
python run.py                   # то же, что run.bat; пакеты ставятся из интернета
```

или вручную:

```
cd app
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python demo.py                  # демо-данные: 3 поставщика, 10 товаров, продажи за 60 дней
python app.py                   # http://127.0.0.1:5000/
```

Вход: `admin` / `admin`. Программа принимает подключения только с этого же компьютера (127.0.0.1). Ключ сессии хранится в `app/secret.key`; если файл удалить, программа создаст новый, и всем придётся войти заново.

Резервная копия — файл `app/floraplan.db`, его достаточно скопировать. `python demo.py` удаляет текущую базу и создаёт демонстрационную заново.

## Устройство

```
app/
  run.bat, run.py запуск: окружение, демо-данные при первом запуске, браузер
  app.py          страницы (маршруты Flask)
  logic.py        продажа по FEFO, прогноз, расчёт заказа
  db.py           подключение к SQLite
  schema.sql      таблицы БД
  demo.py         демонстрационные данные
  templates/      HTML-страницы (шаблоны Jinja)
  static/         стили
```

Таблицы: `users`, `suppliers`, `products`, `batches` (партии), `sales`, `writeoffs` (списания).

## Версии

Релизы базовой редакции выходят из этой ветки с тегами `basic-v*` и не сливаются с `main`: у редакций своя нумерация и свой цикл выпуска. Релизы полной редакции — теги `v*` из `main`.

- **1.2.0** — проверка ввода на сервере: нечисловые и отрицательные цены, сроки и количества, несуществующий товар или поставщик, пустая причина списания — сообщение вместо ошибки сервера.
- **1.1.1** — ключ подписи сессии создаётся случайным при первом запуске и хранится в файле `secret.key` рядом с программой; отладочный режим Flask выключен (включается переменной `FLASK_DEBUG=1`).
- **1.1.0** — таблицы, формы и окно входа выровнены по центру страницы; заголовки и пояснения — тоже.
- **1.0.0** — первая версия базовой редакции: товары, поставщики, приём поставки, продажи по FEFO, остатки и списания, прогноз, расчёт заказа, отчёт; запуск через `run.bat` без интернета.
