# Руководство администратора ФлораПлан

## Варианты установки

### 1. Windows без установки (один компьютер или небольшая сеть)

Скачайте `FloraPlan-<версия>-windows-x64.zip` со страницы [Releases](https://github.com/DarkSwordman999/flower-demand-planning/releases), распакуйте и запустите `ФлораПлан.exe`. База — SQLite в папке `data` рядом с программой, планировщик задач работает внутри программы. Для доступа с других компьютеров и ТСД задайте `FLORAPLAN_HOST=0.0.0.0` (файл `.env` рядом с exe) и откройте порт в брандмауэре. Для HTTPS укажите там же сертификат и ключ в формате PEM: `FLORAPLAN_SSL_CERTFILE=C:\ФлораПлан\cert.pem`, `FLORAPLAN_SSL_KEYFILE=C:\ФлораПлан\key.pem`.

### 2. Сервер в Docker (ПР 7-8, диаграмма размещения)

```bash
git clone https://github.com/DarkSwordman999/flower-demand-planning.git
cd flower-demand-planning/deploy
cp .env.example .env        # задайте DB_PASSWORD, ADMIN_PASSWORD, почту
docker compose up -d --build
docker compose exec api floraplan demo     # при необходимости — демо-данные
```

Готовые образы без сборки: раскомментируйте в `.env` строки `IMAGE_PREFIX=ghcr.io/darkswordman999/flower-demand-planning` и `TAG=1.2.1`, затем `docker compose pull && docker compose up -d`.

Сервисы: `db` (PostgreSQL 16), `api` (FastAPI), `scheduler` (задачи по расписанию), `web` (nginx + интерфейс, порт `HTTP_PORT`, по умолчанию 8080). Данные — тома `pgdata` и `floradata`. HTTPS (требование Б-1) — сервис `proxy` (Caddy): задайте в `.env` домен сервера `DOMAIN` и запустите `docker compose --profile https up -d`. Caddy сам получает и продлевает сертификат Let's Encrypt (порты 80 и 443 должны быть доступны из интернета) и добавляет заголовок HSTS; при `DOMAIN=localhost` или IP-адресе используется сертификат собственного центра Caddy. Порт `HTTP_PORT` после этого стоит закрыть в брандмауэре.

### 3. Из исходников

```bash
cd backend && python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
cd ../frontend && npm ci && npm run build      # интерфейс → backend/floraplan/static
cd ../backend && floraplan demo && floraplan run --host 0.0.0.0
```

## Настройки (переменные окружения `FLORAPLAN_*` или файл `.env`)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | `postgresql+psycopg://user:pass@host:5432/flora_db`; пусто — SQLite в `DATA_DIR` |
| `DATA_DIR` | каталог данных: БД SQLite, `backup`, `outbox`, `inbox_1c` |
| `SECRET_KEY` | ключ подписи токенов входа; не задан — при первом запуске создаётся случайный и хранится в `DATA_DIR/secret.key` (файл не передавайте посторонним: с ним можно подделать вход) |
| `TOKEN_HOURS` | срок действия входа, часов (12) |
| `SHOP_API_KEY`, `ONEC_API_KEY` | ключи интернет-магазина и «1С» (заголовок `X-API-Key`) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TLS` | почта для заказов поставщикам |
| `SHOP_WEBHOOK_URL` | адрес сайта для выгрузки остатков и цен каждые 15 минут |
| `WEATHER_ENABLED`, `LATITUDE`, `LONGITUDE` | погодный сервис Open-Meteo (по умолчанию — Тула) |
| `FORECAST_WORKERS` | процессов для расчёта прогноза: ряды «товар × точка» считаются параллельно, крупные товарные группы делятся на части; `0` — автоматически (по умолчанию): по числу физических ядер, но не меньше 100 рядов на процесс — на малом числе рядов запуск процессов дороже выигрыша; `1` — в одном процессе |
| `HOST`, `PORT`, `NO_BROWSER` | адрес и порт веб-сервера Windows-версии (`127.0.0.1`, `8000`); `NO_BROWSER=true` — не открывать браузер |
| `SSL_CERTFILE`, `SSL_KEYFILE` | HTTPS прямо в сервере (`floraplan run`, Windows-версия): сертификат и ключ PEM |
| `SCHEDULER_ENABLED` | планировщик внутри веб-сервера (в Docker — `false`, работает сервис `scheduler`) |
| `TIMEZONE` | часовой пояс расписания (`Europe/Moscow`) |

Параметры работы (бюджет недели, пороги уценки и расхождений, 30 % для причины изменения заказа, горизонт и час расчёта прогноза, границы уровня обслуживания) меняет директор в интерфейсе: «Администрирование → Параметры».

## Пользователи и роли

«Администрирование → Пользователи» (только администратор): логин, ФИО, роль, салон (для продавца-флориста — его рабочая точка), пароль, блокировка. Из командной строки: `floraplan create-user <логин> <пароль> <роль>`; роли: `admin`, `director`, `buyer`, `storekeeper`, `florist`, `shop_manager`, `analyst`. Места хранения (склад, салоны, интернет-магазин) и причины списания заводит администратор в «Справочниках».

## Задачи по расписанию

| Задача | Когда |
|---|---|
| Прогноз спроса (С-6) | ежедневно в 03:00 (час — параметр «Час ежедневного расчёта») |
| Чеки «1С» из папки обмена (С-5) | ежечасно |
| Прогноз погоды | каждые 6 часов |
| Выгрузка остатков и цен на сайт (С-14) | каждые 15 минут, если задан `SHOP_WEBHOOK_URL` |
| Обезличивание данных покупателей (Б-1, 152-ФЗ) | ежедневно в 01:30: в выполненных и отменённых онлайн-заказах старше срока хранения (параметр, 365 дней) стираются имя, телефон и комментарий |
| Резервная копия (Н-1) | ежедневно в 02:00, хранятся 14 последних |

Результаты и ошибки — «Администрирование → Обмен и расписание».

## Резервное копирование и восстановление

Копии создаются автоматически и по кнопке («Администрирование → Резервные копии»), их можно скачать: SQLite — файл `floraplan-*.db`, PostgreSQL — `floraplan-*.dump` (нужен `pg_dump` в PATH; в Docker-образе он есть).

Восстановление (Н-1) — командой `floraplan restore <имя копии или путь к файлу>`. Перед заменой программа сохраняет текущее состояние копией `floraplan-…-before-restore` (восстановление можно откатить той же командой), проверяет файл копии и после замены обновляет схему БД до текущей версии. На время восстановления остановите программу и планировщик:

```
# Windows
ФлораПлан.exe restore floraplan-20261024-020000.db
# Docker
docker compose stop api scheduler
docker compose run --rm api floraplan restore floraplan-20261024-020000.dump --yes
docker compose start api scheduler
```

## Обновление

Новая версия применяет изменения схемы БД сама при запуске (`floraplan init-db` — миграции Alembic). Перед обновлением сделайте резервную копию. Windows: замените файлы программы, папку `data` оставьте. Docker: `git pull && docker compose up -d --build`.

## Нагрузочное тестирование

Сценарий [`backend/loadtest/locustfile.py`](../backend/loadtest/locustfile.py) имитирует пиковый день (требования П-1 и П-2 ТЗ): сотрудники открывают главную, остатки, прогноз, рекомендации по уценке и отчёты, а «1С» присылает пачки чеков. Запуск на демо-данных:

```
pip install locust
floraplan demo
floraplan run
locust -f loadtest/locustfile.py --host http://127.0.0.1:8000 -u 30 -r 5 -t 5m --headless
```

Результат на одном компьютере с SQLite (30 пользователей, 3 мин, ~1 100 запросов): ошибок нет, медиана отклика 0,16 с, 95 % запросов — до 1,4 с, 98 % — до 1,9 с; чеки «1С» принимаются со скоростью ~1 пачка (5–20 чеков) в секунду, это с запасом покрывает 10 000 чеков в сутки. Самая долгая операция — вход в систему (проверка пароля PBKDF2), когда все пользователи входят одновременно.
