## 1.2.0

Версия исправляет найденные при полной проверке ошибки и доводит сценарии до конца.

- **Безопасность входа (Б-1).** Если ключ подписи `FLORAPLAN_SECRET_KEY` не задан (так было по умолчанию в Windows-версии и при `floraplan run`), токены подписывались общеизвестной строкой — вход под администратором можно было подделать. Теперь при первом запуске создаётся случайный ключ `data/secret.key`; пользователям такой установки после обновления нужно один раз войти заново.
- **Предзаказы резервируются сами (С-14).** Когда товар поступает на место интернет-магазина (приёмка или перемещение), предзаказы, которые теперь можно собрать, резервируются автоматически — первыми те, что доставлять раньше.
- **Прогноз быстрее на ~30 %.** Подбор параметров Хольта–Уинтерса без перебора по сетке (точность та же); крупные товарные группы делятся между процессами, а процессы запускаются, только когда рядов достаточно.
- **Параметры системы проверяются.** Неверные значения (текст вместо бюджета, минимальная уценка больше максимальной) отклоняются с объяснением; новый час расчёта прогноза применяется без перезапуска.
- **Экраны следуют параметрам.** Срок «истекает», границы уценки, порог причины изменения заказа и горизонт прогноза больше не вписаны в интерфейс, а берутся из параметров.
- **Исправления.** Выгрузка ABC/XYZ-анализа в XLSX; заблокированные пользователи видны в списке, а занятый логин даёт понятную ошибку; сбой почтового сервера при отправке заказа — сообщение с причиной, заказ остаётся «Утверждён»; окно печати этикеток не блокируется браузером; удаление событий календаря — только у закупщика и аналитика; маска короткого телефона покупателя.
- **Проверки.** Сквозные тесты экранов «Каналы продаж» и способа отправки заказа поставщику; CI на актуальных версиях GitHub Actions (Node.js 24).

Обновление: замените программу, папку `data` оставьте — изменения схемы БД применятся при запуске.

## 1.1.0

Версия закрывает оставшиеся нефункциональные требования ТЗ.

- **Каналы продаж (Р-4).** Маркетплейс или второй сайт подключается в «Администрирование → Каналы продаж» без изменения программы: свой ключ API, место хранения для остатков и резерва, коэффициент цены, номера заказов `код:номер`.
- **Адаптеры отправки заказов поставщикам (Р-4).** В карточке поставщика выбирается способ: XLSX по e-mail или JSON в API поставщика.
- **HTTPS (Б-1).** Сертификат прямо в программе (`FLORAPLAN_SSL_CERTFILE`, `FLORAPLAN_SSL_KEYFILE`) или прокси Caddy с Let's Encrypt в Docker (`docker compose --profile https up -d`).
- **152-ФЗ (Б-1).** Имя, телефон и комментарий покупателя в закрытых онлайн-заказах обезличиваются через заданный срок (по умолчанию 365 дней).
- **Восстановление из копии (Н-1).** Команда `floraplan restore` со страховочной копией текущего состояния; работает для SQLite и PostgreSQL, в том числе в Docker.
- **Параллельный прогноз (Р-1).** Товарные группы считаются в нескольких процессах (`FLORAPLAN_FORECAST_WORKERS`).
- **Нагрузка (П-1, П-2).** Нагрузочный тест на 30 пользователей: ошибок нет, 95 % запросов быстрее 1,4 с; исправлены блокировки SQLite при одновременной записи и долгий вход.
- **Исправления.** Windows-версия читает `HOST`, `PORT` и другие настройки из `.env` рядом с программой; неизвестный адрес `/api/…` отвечает 404; резервная копия снимается с подключённой БД.

## Что умеет

- **Партионный учёт** со сроком «годен до», расход по FEFO, перемещения, списания с актами, инвентаризация.
- **Приёмка на ТСД**: сканирование упаковок, брак, сокращение срока, фитосанитарный контроль, акт расхождений при отклонении больше 2 %, этикетки партий.
- **Прогноз спроса** по товарам и точкам на 14 дней с квантилями P50/P80/P95: сезонная наивная модель, Хольт–Уинтерс, метод Кростона, праздничные коэффициенты, очистка дней дефицита, поправка на погоду; версии модели публикуются только при WAPE не хуже действующей.
- **Расчёт заказа поставщику** по модели «продавца газет»: Q = max(0, D − S − Z) с учётом сроков годности, кратности, минимальной суммы, бюджета недели (сокращение по ABC, утверждение директором), сценариев праздников.
- **Заказы поставщикам**: согласование, отправка XLSX по e-mail, статусы до приёмки и закрытия.
- **Уценка** партий с истекающим сроком по прогнозу продаж, выгрузка цен в кассы.
- **Интеграция**: чеки «1С:Розница» (HTTP-сервис, папка обмена, CSV/JSON), API интернет-магазина с резервированием и предзаказами, погода Open-Meteo.
- **Отчёты**: продажи и маржа, списания, оборачиваемость, точность прогноза, ABC/XYZ, закупки — с выгрузкой в XLSX.
- 7 ролей, журнал действий, параметры системы, резервные копии, задачи по расписанию.

## Как запустить

- **Windows**: скачайте `FloraPlan-…-windows-x64.zip`, распакуйте, запустите `ФлораПлан.exe` — при первом запуске программа предложит загрузить демо-данные. Вход: `admin`/`admin`, демо-пользователи `director`, `buyer`, `storekeeper`, `florist`, `shop`, `analyst` с паролем `demo`.
- **Сервер (Docker)**: скачайте исходный код релиза, в каталоге `deploy` скопируйте `.env.example` в `.env`, задайте пароли и выполните `docker compose up -d --build`.

Подробно — [руководство пользователя](https://github.com/DarkSwordman999/flower-demand-planning/blob/main/docs/USER_GUIDE.md), [руководство администратора](https://github.com/DarkSwordman999/flower-demand-planning/blob/main/docs/ADMIN_GUIDE.md), [интеграция](https://github.com/DarkSwordman999/flower-demand-planning/blob/main/docs/INTEGRATION.md).
